Current implementation work
---------------------------

1. Failed module fetches: remove rejected network/HTTP/MIME responses from
   TRust's shared response cache, retaining the precise fetch each existing
   waiter joined. A later import can retry; successful evaluation remains
   cached. HTML #fetch-a-single-module-script; Servo PR #46919.
2. Responsive image preload: share image source selection for link
   href/imagesrcset/imagesizes, with DPR, width descriptors, media, base URL,
   mutation and removal handling. HTML #preload, #create-a-source-set,
   #update-the-source-set; Servo PR #47103.
3. FontFaceSet: connect CSS rule objects to FontFace identity, matching,
   decoding/loading and document font installation. CSS Font Loading 3
   #font-face-css-connection, #font-face-set-load and CSS Fonts 4
   #font-style-matching; Servo PR #47564.
4. CORS: require explicit Authorization in Access-Control-Allow-Headers even
   without credentials. The post's PR #47600 explicitly adopts a deviation
   from Fetch; TRust's preflight already had that deviation while its
   preflight cache correctly excluded Authorization from wildcard matching.
   Follow Fetch #cors-preflight-fetch-0, not that compatibility change.

Second implementation batch (user-approved scope)
------------------------------------------------

5. Column subgrid: inherited inline tracks, line names/areas, shared gaps,
   child intrinsic contributions, forced stretch on the subgridded axis,
   nested/both-axis subgrids, direction reversal and CSSOM used-span values.
   CSS Grid 2 #subgrids, #algo-track-sizing, #resolved-track-list-subgrid.
6. Demand-driven fonts: CSS and script-added fonts load on actual text use
   in layout, canvas and SVG, with family/style/weight/width/Unicode-range
   matching. Unused and hidden faces remain unloaded; fonts.ready waits for
   used faces and their fallbacks. The static renderer follows the same
   demand loop. Document ownership, redirected stylesheet referrers and
   stylesheet Referrer-Policy are preserved. The Fontique query now visits
   all matching Unicode subsets in reverse CSS rule order, without falling
   through to a different weight in the same CSS family.
7. Text transforms: Unicode-aware capitalization, full-width, full-size-kana
   and math-auto, including inline word context and contextual Turkish/Azeri,
   Lithuanian, Dutch and Greek casing. Expanding/contracting mappings preserve
   original DOM offsets and copied text, including transforms applied only
   through ::first-letter. Unicode tables have a reproducible
   offline generator and carry the Unicode License V3.
8. Animation composition: replace/add/accumulate lists and per-keyframe
   overrides compose endpoints with the underlying effect before interpolation.
   Includes numeric/length/repeatable values, transform/filter/shadow lists,
   scale/matrix accumulation and transition interaction. Non-additive values
   replace (including colors under the consulted CSS Values 4 snapshot).
9. PerformanceTiming: Window-only interface, branded readonly getters,
   same-object performance.timing, live navigation timestamps, Web IDL
   toJSON and cross-window receivers. Workers do not expose this interface.
10. IPv4/IPv6 connection fallback (additional reported bug): one shared TCP
    connector for HTTP/HTTPS, WebSocket, Gemini, Gopher/Gophers, Telnet/TLS,
    DICT, Finger and WHOIS. Interleave address families in OS preference
    order; start the next attempt after 250ms, or after at least 100ms when
    an attempt fails. Keep earlier attempts alive, cancel losers on success
    and bound DNS plus TCP to 15 seconds (shorter caller budgets still apply).
    HTTP connection timing preserves separate DNS/TCP boundaries. HTTP/3
    already has its own bounded staggered QUIC attempts.

Third implementation batch (user-approved scope)
-------------------------------------------------

11. Font display: first-use timelines belong to individual faces and survive
    src fallback/shared URLs. Block periods hide glyph ink while retaining
    metrics, selection and SVG geometry; swap/failure deadlines wake the page
    without polling. Late optional/fallback data stays available to Canvas
    while CSS continues using fallback. CSS-connected faces retain the bytes
    from their successfully loaded source. CSS Fonts 4 #font-display-timeline,
    #font-display-desc; HTML #canvastextdrawingstyles.
12. SVG text transforms use the same Unicode mappings as HTML, with context
    spanning tspan/chunk boundaries and original shaping-cluster indices for
    SVG positioning and text APIs. innerText on an inline subtree uses its
    surrounding inline context. CSS Text 4 #text-transform-mapping and
    #text-transform-order; SVG 2 #TermAddressableCharacter and character-to-
    glyph positioning; HTML #rendered-text-collection-steps.
13. Grid sizing rechecks column contributions using resolved/aligned row sizes
    and performs at most one additional column/row pass. Definite row estimates
    include distributed gaps, and vertical text intrinsic measurements retain
    the available row height in their cache keys. CSS Grid 2 #algo-grid-sizing
    steps 1-4; CSS Writing Modes 4 #orthogonal-flows and #orthogonal-auto.
14. Eligible additive transform/opacity stacks are retained and sampled by
    the graphical compositor, including their per-keyframe composition and
    easing. Ordinary frame sampling and font-readiness checks avoid layout;
    CSSOM geometry reads flush deferred geometry. Terminal rendering and
    unsupported combinations continue using the actor.
    Web Animations 1 #effect-composition and
    #the-effect-value-of-a-keyframe-animation-effect; CSS Animations 2
    #animation-composition. All use the same local CSSWG snapshot above.
15. Workers share the FontFace/FontFaceSet implementation with Window, using
    independent initially empty font sources, their own font-loading tasks,
    resource base URL and OffscreenCanvas environment. Transferred canvases
    use the receiver's fonts. Blob workers use their settings origin for CORS,
    independently of the script URL used for source resolution. CSS Font
    Loading 3 #fontfacesource-workers; HTML #canvastextdrawingstyles and
    #concept-settings-object-origin; Fetch #concept-request-origin.
    No trust-js engine changes.
16. Reported PMVHaven crash: reproduced twice in the existing release browser.
    A video update during backdrop rendering deleted a CPU image registration
    still referenced by queued draws; Hybrid's CPU effect renderer and then
    the CPU fallback both panicked, followed by process termination. Each
    presentation now shares a lazy immutable image/video snapshot across its
    main and offscreen passes. Image bytes and revision are read atomically.
    Filter Effects 2 #backdrop-filter-operation / #BackdropRoot and HTML
    #the-video-element. Reproduction and validation logs: target/servo-third/.

Remaining features to consider
-----------------------------

- Touch-action and axis-locked panning (implementation complete; final
  verification in progress). Native touch PointerEvents now have independent
  contact IDs, implicit/explicit capture, cancellation, iframe routing and tap
  activation. Panning freezes policy and transformed axes at gesture start,
  follows containing-block scroll ancestry, and preserves wheel/mouse input.
  CSSOM validates and canonically serializes touch-action. Native pinch zoom
  and legacy TouchEvent dispatch are not introduced by this panning feature.
  Pointer Events #the-touch-action-css-property; Servo #47043 and #46983.
- Accessibility semantics (explicitly deferred by the user). The geometry/AccessKit bridge exists, but the role
  mapping lacks many landmarks, live regions and structural roles in the
  post. Extend native role/state/name mappings with ARIA and HTML-AAM tests,
  including multiple-token fallback roles and dynamic updates. Servo #47318.
- Service workers and CookieStore (fourth batch in progress below). The initial
  audit found CacheStorage but no working service-worker registration or
  CookieStore. The remaining implementation includes request interception,
  client messaging/navigation, module validation and navigation preload.
  Servo #47044 and #47220.
- Persistent HTTP cache (explicitly deferred by the user). PageCache is an in-memory document response/preload
  cache. Persistent caching needs RFC 9111 freshness/revalidation, Vary and
  request-context partitioning, bounded storage and user clearing controls.
  It is distinct from the script CacheStorage API. Servo #43819.
- LargestContentfulPaint. No exposed interface or supported performance
  entry type. Requires paint-backed candidate tracking, text/image/video
  poster geometry, timing, element/url fields and PerformanceObserver
  delivery, not just an interface constructor. Servo #46553, #47475,
  #43376, #43378 and #47212.
- Further grid work: nested orthogonal subgrids and full logical-axis grid
  layout still need dedicated conformance coverage. The third batch covers
  row-constrained vertical text and one bounded cross-axis sizing feedback
  pass, including distributed row gaps.
- Further compositor work: mixed layout-property stacks, active underlying
  transitions, SVG-dependent targets, 3D transforms and singular initial
  transforms retain the actor path. Their existing composition semantics
  remain covered by the actor tests.
- A separate intermittent desktop startup SIGSEGV remains unresolved. One
  launch of the updated build failed before page/script diagnostics. The
  crashing thread's frames were in libnvidia-glcore.so.610.57.04; this stack
  alone does not establish the underlying cause. Five subsequent independent
  file-page launches and normal closes succeeded. Local evidence is retained
  in target/servo-third/core-info.txt, core-stack-modules.txt, core-8502 and
  startup-file-results.json. This differs from the reproduced image-registry
  panic fixed in item 16.
- Incremental A/AAAA resolution and NAT64 synthesis: TCP address racing uses
  the system's combined resolver with a bounded wait. It implements RFC 8305
  §§4–5 after resolution, not that RFC's complete asynchronous DNS algorithm.

Other comparisons requiring dedicated regression work
----------------------------------------------------

Navigation/history/initial about:blank, cross-origin Window/Location, font
matching ties, shaping across inline boundaries, sticky scrollable overflow,
pointer-capture transitions and zero-width inline edges have related TRust
implementations. This review did not establish parity with every referenced
Servo edge-case fix. Use the linked reduced WPT cases and authoritative local
standards before deciding whether each needs a change. WebDriver is not
implemented. Servo's SpiderMonkey, Android/OpenHarmony, embedder API and
threadboost changes concern a different engine/platform architecture.

TextEvent is not a missing constructor: Servo #47391 adds legacy
document.createEvent("TextEvent") and initTextEvent(), which TRust already
supports. The UI Events IDL has no public constructor.

Messaging transport is implemented (2026-10-19). One natively-held
structured-serialize packet is the only new transport: ServiceWorker
postMessage serializes first, takes its source and origin from the
incumbent global through the native callback boundary in Windows
(a worker Realm is its own incumbent), applies Should Skip Event,
then runs the destination worker under an event lease and lands as
an ExtendableMessageEvent (messageerror if deserialization fails).
Client postMessage serializes with the Client's relevant settings
and enqueues on the target's native, initially disabled client
message queue (256 packets, 32MiB); onmessage, startMessages,
DOMContentLoaded and worker start enable it, and the container
takes one packet per task, so a wake hint can never drop a message.
Skipped events, failed startups, over-bound discards and client
teardown release port/stream/OffscreenCanvas transfers natively,
recursively for packets queued on discarded ports. Messages may
run installing and waiting workers, including a bounded waiting-lease
in begin_event. The worker/worklet incoming paths and the worker
slot map now use bootstrap JSON.parse and Reflect/WeakMap/Object
captures, and empty-host clientState traffic no longer fails.

Touch input implementation
--------------------------
Native desktop touch contacts now reach the page as trusted PointerEvents with
per-top-level pointer IDs, first-contact primary status, implicit/explicit
capture, cancellation and tap activation. A contact is canceled when native
scrolling takes over, the tab hides, focus is lost or browser UI interrupts it.
Multiple contacts keep their own state; idle contacts schedule no timer work.

CSS touch-action is parsed, validated and serialized in canonical order. Native
panning snapshots the hit element's applicable ancestor policies and transformed
coordinate systems, stops policy propagation at scroll/document boundaries, and
keeps the initial direction and axis for the gesture. Nested scroll chaining
uses containing-block scroll ancestry, available scroll ranges and overscroll
policy. Rejected gestures continue to deliver pointer movement to the page.

Compatibility mouse transitions track the effective position across pointer
types and nested documents, while physical mouse hover/position remains separate.
Touch taps use existing form, focus, link and browser UI activation paths. This
work adds panning and Pointer Events; pinch zoom and native legacy TouchEvent
streams are separate capabilities and are not implemented by this change.

Standards consulted locally: Pointer Events 49c398264c8d (pointer event dispatch,
capture, stream suppression, touch-action and compatibility mouse mapping),
Compatibility Standard d2417c512256 (touch-action grammar), CSSWG 81c27f686901
(Transforms, Overflow, CSSOM), and UI Events 8c1b809. These are local official
snapshots, not a fresh upstream verification.

The manual acceptance page is src/fixtures/touch_input.html. DIAGNOSTICS.md lists
