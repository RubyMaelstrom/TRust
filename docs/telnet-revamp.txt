TRust Telnet revamp implementation plan
======================================

Priority: responsiveness, faithful remote presentation, and identical session
semantics in the terminal and desktop frontends. Keep controls in COMMAND mode.

[x] 1. Transport and protocol
    Replace libmudtelnet with an incremental, bounded RFC 854 parser and
    independent RFC 1143 option state machines. Correct IAC, NVT, suboptions,
    LINEMODE, TTYPE, and cancellation. Bound queued bytes; make writes,
    reads, close, and resize independent of frontend rendering progress.
[x] 2. Shared terminal/session model
    One VT parser, device-reply path, encoding, negotiated input state,
    key/paste/mouse encoder, and local echo policy used by both frontends.
    Tag desktop events with session identity. Surface rejected input.
[x] 3. VT correctness
    Maintain an owned vt100 engine fork for general engine defects. Fix
    wide-cell resize safety, DEC graphics, cursor/erase/tab/wrap modes,
    rendition attributes, streaming queries, and Unicode cluster handling.
[x] 4. Frontend parity and uncluttered presentation
    Route remote shortcuts and paste consistently. Collapse redundant input
    chrome in character mode. Put mode, encoding, newline, reconnect, status,
    and scrollback actions in COMMAND mode. Keep remote geometry accurate.
[x] 5. Responsiveness and reading
    Batch bounded work per frame, retain unchanged graphical rows, preserve
    scroll position, hide the live cursor while reading history, and provide
    terminal search/copy and accessible desktop terminal text.
[x] 6. Verification and handoff
    Focused protocol and VT conformance regressions, loopback stress tests,
    frontend tests, formatting/static checks, and release builds of both
    trust and trust-desktop. Record measured results and remaining limits.

Standards consulted
-------------------
Local official RFC snapshot downloaded 2026-09-06 (not represented as a
current-upstream/errata-integrated verification): RFC 854, 855, 856, 857,
858, 859, 1073, 1079, 1091, 1143, 1184, 1372, 1572, 2066, 3629.
RFC 1143 and RFC 2066 are Experimental specifications.
ECMA-48 fifth edition, June 1991, and xterm control-sequence documentation
(Patch 411, 2026-08-23) were fetched from their official sources to fill a
local-library gap during the review. Consult clauses again as each change
is implemented; references belong beside the relevant algorithms/tests.

Acceptance artifacts are release builds. Installation, promotion, and push
remain separate user-authorized steps. Preserve unrelated working-tree edits.

Implementation and capability boundary
--------------------------------------
Protocol framing and transport live in src/telnet/protocol.rs and session.rs.
Shared terminal/input/reading behavior lives in src/terminal.rs; the owned
vt100 fork fixes the actual engine. src/terminal_tui.rs and terminal_view.rs
are presentation adapters. Neither frontend has its own VT parser or probe
scanner. The desktop session wrapper also guards every event by session ID.

The receive parser is incremental and IAC-safe. Unsupported options are
refused. Subnegotiation payloads are capped at 16 KiB; malformed/oversized
frames end that session with an error. Input admission has both a 1 MiB
byte budget and a 1,024-command limit. Close and the latest resize bypass
that FIFO. Frontend delivery and partial socket writes remain independently
serviceable, with bounded pending output/wire high-water marks. DNS/TCP and
TLS setup have 15-second stage deadlines; established idle connections have
no read timeout. Dropping the session cancels its task and socket.

LINEMODE keeps EDIT and ECHO independent, honors TRAPSIG, programmable soft
tabs and literal echo, and exports fixed supported SLC characters. SLC
NOSUPPORT disables local interpretation. Unknown or unsupported assignments
are counter-proposed/refused, not falsely acknowledged. LFLOW is refused:
local scrollback reading is not advertised as XON/XOFF or TCP SYNCH.

VT coverage includes DEC graphics/charset shifts, IND/NEL, CUP/HVP and origin
relative addressing/replies, programmable tabs, insert/delete/erase/scroll,
auto-wrap and insert/newline modes, alternate buffers, cursor shape, reverse
video, application cursor/keypad input, modifiers/function keys, bracketed
paste, and X10/normal/UTF-8/SGR mouse encodings. Both adapters preserve cell
geometry, including Unicode clusters split across reads. Wide-cell edits
and dimensions down to one column are regression-tested. Primary transcript
reflow preserves hard/soft breaks; alternate screen resizing clips cells.
Oversized edit/scroll counts are bounded to the screen rather than expanded.

The desktop keeps unchanged rows and a complete display list at rest, and
only schedules cursor/text animation while needed and focused. Slow/rapid
text blink use distinct rates. TUI blink is delegated to the host terminal.
Search includes soft-wrapped lines; changed output invalidates stale hits
and find-next/find-prev rebuild results on demand, outside the receive path.
Copy/accessibility omit concealed glyphs. The native accessibility tree has
a Terminal node and a separate line-input node; hidden input is not exposed.
COMMAND controls do not modify terminal cells or change character-mode NAWS.
Reconnect retains the draft and current input settings, without resending it.

Remaining limits and later features
----------------------------------
This revamp is an ANSI/BBS terminal with selected VT/xterm extensions, not a
claim of full xterm or every historical VT model. TTYPE cycles ANSI, VT100,
VT100, ANSI; full XTERM is no longer advertised. Device replies describe a
conservative VT100-class target, not advanced graphics capabilities.

DEC double-width/double-height lines, complete national replacement sets,
dynamic OSC palettes, DCS/SIXEL/Kitty graphics, DECRQSS/extended capability
queries, and arbitrary terminal font changes remain outside this target.
SGR double underline is retained and painted on desktop; the Ratatui host
adapter falls back to single underline. Host fonts, emoji shaping/width,
clipboard policy and blink support can also limit native TUI presentation.
A wide character in a one-column viewport becomes a replacement character.
One grapheme is capped at 256 UTF-8 bytes; history uses at most one million
cells / 10,000 rows; advertised dimensions are capped at 1,024 x 512.

CHARSET negotiation, LFLOW, TCP urgent-data SYNCH, MUD compression/structured
extensions (MCCP/GMCP/MSDP/MTTS), persistent connection profiles, session
recording/replay, automation and file transfers are separate follow-up work.
They are not silently advertised as implemented. Accessible output is polite;
announcement granularity still depends on the platform assistive technology.
Committed desktop IME text uses the shared encoder; character-mode preedit
presentation and interaction with real input methods need further UX work.

Validation record (updated at handoff)
-------------------------------------
- Focused parser/transport tests: 20 passed, including a stalled TLS handshake,
  saturated output delivery, bounded input, independent resize/close and
  exact input ordering under a flood.
- Browser-check transport measurement, 300 loopback samples with frontend
  output deliberately undrained: enqueue-to-peer-read p50 40 us, p95 464 us,
  p99 576 us, max 645 us. Drop-to-peer-close 292 us. These exclude rendering.
- Final terminal/affected rendering tests: 71 passed, one existing diagnostic
  ignored. Final desktop tests: 43 passed, one existing diagnostic ignored.
- Two full library runs exposed separate intermittent HTTP timing assertions
  (resource element timestamps and redirectEnd rounding); each passed alone.
  Both failures also reproduce in the pre-revamp release test binary: the
  resource-elements test failed in one of three repeated full runs, and
  the redirect timing test failed in 5 of 50 isolated runs. Two other old
  full runs passed all 1,667 active tests. No HTTP implementation or timing
  test was changed for this Telnet work. The new tree passed a full run of
  1,699 tests before the final cursor-focus test was added; the latest run
  passed 1,699 with the same existing resource-timing flake and 19 ignored.
- Final formatting, Clippy and git diff --check are clean.
- cargo build --release --bin trust --bin trust-desktop succeeded on the final
  application source; an immediate repeat completed without recompilation.
- The actual release terminal frontend passed a PTY/local-server smoke test:
  negotiation, keys including Ctrl+C, bracketed paste and CR NUL encoding,
  query-position CPR, COMMAND geometry/cursor preservation, resize, close,
  and clean exit. At an 80 x 24 host size, NAWS is 78 x 21; at 100 x 30,
  it is 98 x 27. The old character input strip consumed three extra rows.
  Over 100 samples each, key-to-peer delivery was p50 0.770 ms / p95 1.293 ms /
  p99 1.718 ms at rest, and p50 0.462 ms / p95 0.751 ms / p99 1.065 ms under
  output load. COMMAND close-to-peer was 0.857 ms. A settled one-second
  sample observed zero process CPU ticks. These are local scheduling/socket
  measurements, not Internet latency or input-to-visible-pixel measurements.
- Native Wayland release desktop smoke tests passed with both CPU and hybrid
  rendering. The hybrid trace confirmed the NVIDIA GB10 adapter, with no
  fallback. Both exercised live ANSI/DEC/Unicode scenes, cursor-query ordering,
  geometry queries, 100 update/query round trips and disconnect while keeping
  the application alive. Server-update-to-cursor-reply measurements:
                      p50         p95         p99
      CPU           0.529 ms    1.181 ms    5.586 ms
      Hybrid        0.587 ms    2.911 ms   12.688 ms
  These include the native event loop but do not measure native key delivery
  or presentation latency. Renderer traces verify actual scene submission;
  this was not a visual pixel comparison, native keyboard/IME automation,
  or a screen-reader usability test. The forced-X11 diagnostic could not
  start because this machine lacks libxkbcommon-x11; Wayland worked normally.
